# MetraCards MCP Auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add personal local Firebase auth to metracards-mcp (browser Google/Apple login, credential store, ID token refresh, Bearer on API client, auto `POST /users` upsert) with tools `auth_login`, `auth_logout`, `auth_status`.

**Architecture:** Layered `config` → `auth/*` (store, token provider, browser login) → `clients` (Bearer + upsert) → `tools` → `server`. Stdio only. Same auth contract as metracards-web.

**Tech Stack:** Node 20+, TypeScript, native `fetch`/`http`/`fs`, Firebase Web SDK CDN in login page, Secure Token REST for refresh, existing MCP SDK + zod + dotenv.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-08-01-mcp-auth-design.md`
- Never log or return tokens from MCP tools.
- Credential file mode `0600`; default `~/.config/metracards-mcp/credentials.json`.
- `health_check` stays unauthenticated.
- Log only with `console.error` on stdio.
- Tests: `node --experimental-strip-types --test src/**/*.test.ts`
- Skip git commit steps unless the user asked to commit.
- Firebase env vars (no `VITE_` prefix): `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID`, `FIREBASE_STORAGE_BUCKET`, `FIREBASE_MESSAGING_SENDER_ID`, `FIREBASE_APP_ID`.

### Task 2: Token provider

**Files:**
- Create: `src/auth/token-provider.ts`
- Create: `src/auth/token-provider.test.ts`

**Interfaces:**
- Consumes: `CredentialStore`, `firebase.apiKey`
- Produces: `TokenProvider` with `getIdToken(): Promise<string>`, `clearCache()`, `getStoredProfile(): Promise<StoredCredentials | null>`

- [ ] **Step 1: Implement refresh**

`POST https://securetoken.googleapis.com/v1/token?key=${apiKey}`  
Body (form): `grant_type=refresh_token&refresh_token=...`  
Parse `id_token`, `expires_in`, optional new `refresh_token` (persist if rotated).

Cache id token until ~60s before expiry. If no credentials → throw `AuthRequiredError` with message telling user to call `auth_login`. If refresh fails → `clear()` store and throw.

- [ ] **Step 2: Unit tests with mocked fetch**

Cover: cache hit, refresh call, missing credentials error.
